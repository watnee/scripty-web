Scripty API — link relations

Responses from /api use HAL. Standard IANA relations such as self keep their usual meaning; the project-specific relations below are namespaced scripty:* via a HAL curie, and each links here by its name. A client should follow these relations rather than hard-coding URLs — presence of a mutation relation also signals that the current user is allowed to perform it. Send Accept: application/prs.hal-forms+json to additionally receive _templates describing each mutation's HTTP method and fields.

Navigation

RelationLeads to
projectsThe collection of projects.
projectThe owning project of the current resource.
blocksThe screenplay blocks of a project.
charactersThe characters (people) in a project.
actorsThe actors, optionally scoped to a project.
actorThe actor cast in a character.
usersThe collection of users.
teamsThe collection of teams.
documentsA project's text documents (songs and notes).
documentA single text document.
songsA project's song documents.
songThe song a block or version belongs to.
songBlocksThe lyric blocks of a song.
notesA project's note documents.
audioRecordingsThe recordings kept with a song — voice memos, demos, reference tracks. Advertised on every song, empty or not, and to readers as well as editors: hearing a demo needs no permission to write.
audioRecordingA single recording. Everything on the resource describes the file; the file itself is behind audioFile.
uploadAudioAdd a recording to this song. POST a multipart/form-data body with a file part holding an MP3, M4A, WAV, AIFF, FLAC, OGG or WebM of 25 MB or less, and optionally title and durationMs parts. Nothing on the server decodes audio, so the duration is whatever the uploader measured — omit it and the recording simply has none. Advertised on the recordings collection for an editor.
audioFileThe bytes of a recording, served as the type it was uploaded as. The one relation in this vocabulary that answers with something other than JSON: play it, download it, or hand it to a share sheet. Supports byte ranges, so a player can seek.
renameAudioRename a recording. PUT {"title"}. The file is untouched; only what the writer calls it changes.
deleteAudioDelete a recording, bytes and all. Unlike a deleted lyric line this does not go to the trash — nothing here keeps a file after it is thrown away. Answers with the song's remaining recordings.
commentCountsHow many comments sit on each element of a project, keyed by block id, as {"counts": {"12": 3}}. Advertised on a non-empty block collection so a client can mark the discussed elements without a request per element; elements with no comments are absent rather than zero.
songEditionsA song's named editions — an alternate lyric, a rewrite, a cut for a different scene. The song counterpart of editions, hung off the document rather than the project; the resource is shaped identically.
songEditionA single song edition.
versionsThe version history of a project or song.
songVersionsThe version history of a song, as the collection relation embedding its snapshots. A song snapshot reports the title and lyric line count where a screenplay's reports scenes and elements.
versionA single saved version.
headshotAn actor's headshot image. Present only when the actor has one.
forgotPasswordAsk for a password-reset email. POST {"email"}. Always answers 202 with the same message, whether or not the address is registered. Advertised on the 401 challenge, since nothing behind the sign-in can advertise it.
resetPasswordSet a new password using the token from a recovery email. POST {"token","password"}. GET the same URL with ?token= to ask whether a token is still good and whose account it belongs to.
setHeadshotStore a headshot for this actor. POST a multipart/form-data body with a headshot part holding a JPG, PNG, WebP or GIF of 5 MB or less. Answers with the refreshed actor.
removeHeadshotDELETE this actor's headshot. Present only when the actor has one. Answers with the refreshed actor.
syncStatusWhether a project changed since a given revision.
undoRedoStatusWhether undo/redo is currently available.
capitalizationPreferencesThe signed-in user's auto-capitalization settings.
contactSuggestionsName/email suggestions for a project's invite forms.
accountThe signed-in user's own account. Not an admin's view of someone else's.
passkeysThe passkeys registered to the signed-in user. Present only where passkeys are configured.
passkeyA single registered passkey.
registerPasskeyBegin registering a passkey: POST (no body) answers the standard WebAuthn creation options under publicKey plus a challengeId, with a verify link to POST {"challengeId","label","credential"} back to. The ceremony state lives behind the challengeId — no cookies involved — and expires after a few minutes, single-use.
passkeyLoginBegin a passkey sign-in. Advertised on the 401 challenge, like forgotPassword: the caller is signed out by definition. POST (no body) answers WebAuthn request options under publicKey plus a challengeId, with a verify link; a verified assertion answers {"username","token"} — a bearer token the client sends as Authorization: Bearer in place of Basic, since a passkey leaves it with no password.
verifyThe second half of a WebAuthn ceremony: where the authenticator's response is POSTed.
revokeTokenDELETE, with the bearer token in the Authorization header, to revoke it — the API's sign-out for a passkey session.
editionsA project's named editions of the screenplay — a shooting draft, a table read, a production revision. editionId is accepted on blocks, imports and version history; this is how a client learns which ids exist.
editionA single script edition.
commentsThe comments left on one element.
commentA single comment.
activityA project's activity feed — who changed what, most recent first.
activityEntryA single entry in the activity feed.
invitationsThe outstanding invitations to a project.
invitationA single invitation.
trashThe trash a deleted thing went to. Advertised alongside delete so a client can say where the deletion can be undone from.
trashedProjectsProjects the signed-in user has deleted and can still restore.
trashedProjectA single deleted project.
deletedBlocksElements deleted from a project, still restorable.
deletedBlockA single deleted element.
deletedDocumentsSongs and notes deleted from a project, still restorable.
deletedDocumentA single deleted song or note.
archivedThe archive a set-aside thing went to — songs and notes on a project's document collection, whole screenplays on the project collection. Not a second trash: nothing here is on a clock, and an archived thing is still whole, openable and part of a project bundle export — it is only kept out of the list. Advertised even when the archive is empty, since a list can be empty because everything in it was archived.
archivedDocumentsSongs and notes archived from a project.
archivedDocumentA single archived song or note. Carries archivedAt and no purge date, since nothing expires out of the archive.
archivedProjectsScreenplays the signed-in user has archived — wrapped productions kept out of the project list without being deleted.
archivedProjectA single archived screenplay. Carries archivedAt, lastEdited and its teams, and no purge date; it links to project because an archived screenplay is still openable in place.
deletedSongBlocksLyric lines deleted from a song, still restorable. Kept apart from deletedBlocks because a line and a screenplay element are restored by different services and carry different fields.
deletedSongBlockA single deleted lyric line. purgeAt is absent where the deployment keeps trashed lines until someone deletes them for good.
accessEveryone who can already see a project, with why (their role, or the team carrying it) and whether they can write. Not the same as invitations: role and team membership grant access without one.
accessUserOne person who can see the project.
inviteTeamOne team in the inviteTeams collection: an id and a name to choose from when inviting a collaborator.
projectTeamOne team in the projectTeams collection: an id, a name, and an assigned flag saying whether the project belongs to it now.

Mutations

Present only when the current user may perform them.

RelationMethodAction
createPOSTCreate a new resource in a collection.
createBelowPOSTInsert a new block directly after this one.
createInitialPOSTAdd the first block to an empty script.
updatePUTReplace the resource's editable fields.
deleteDELETEDelete the resource.
movePUTReorder a block within its document.
reorderPOSTReorder documents within a project.
setTypePUTChange a block's screenplay element type.
replacePOSTReplace one occurrence of find with replace inside this block — the single-step counterpart of bulkReplace. Both are literal, never regular expressions. occurrence is the zero-based match to swap and defaults to the first; an out-of-range value changes nothing.
setHighlightPUTSet or clear a song block's highlight.
setAuditionsPOSTReplace, wholesale, the characters an actor auditions for in a project. Advertised on a project-scoped actor only; an empty list clears them.
changePasswordPOSTChange the signed-in user's own password. The current password is required.
toggleBookmarkPOSTToggle a block's bookmark.
togglePinnedPOSTToggle whether a block is pinned.
toggleDefaultPOSTToggle a project as the user's default.
insertPOSTInsert content into a text document.
duplicatePOSTDuplicate a text document.
changeTypePOSTChange a document between song and notes. Send {"type": "SONG"} or {"type": "NOTES"}; any other value is read as SONG.
restorePOSTRestore a saved version as current.
undoPOSTUndo the last change.
redoPOSTRedo the last undone change.
shareEmailPOSTEmail a song to a recipient.
bulkShareEmailPOSTEmail a selection of songs to a recipient in one message. Rides on the document collection; takes ids and email, and answers with how many were sent and their titles, since anything in the selection that is not a song is skipped.
importProjectPOSTCreate a project by importing a file.
importDocumentPOSTCreate a document by importing a file — .txt, .fountain, .docx, .doc, .fdx, .epub, .pdf, or a .musicxml/.mxl score, whose lyrics become the song's lines and whose title becomes its own.
importScriptPOSTReplace an existing project's script by importing a file.
replaceFromArchivePOSTRead a whole .scripty.json archive into this project rather than into a new one — the other direction of exportArchive, and how a copy written on a signed-out device comes home as the same project instead of a second one. Songs and notes are matched on the uid the file carries for each and written where they stand, keeping their ids, lyric lines and version history; only ones the file does not name go to the trash. The script it replaces is auto-saved to the version history first, and only the default edition is touched.
exportGETDownload the script as Fountain.
exportPdfGETDownload the script as PDF.
exportDocxGETDownload the script as Word (.docx).
exportFdxGETDownload the script as Final Draft (.fdx).
exportEpubGETDownload the script as EPUB.
exportArchiveGETDownload the whole project as a re-importable .scripty.json archive.
exportProjectsGETDownload every project the caller can see as one re-importable bundle. Add ids to narrow it to a selection.
exportSongTxtGETDownload one song as text.
exportSongPdfGETDownload one song as PDF.
exportSongDocxGETDownload one song as Word (.docx).
exportSongEpubGETDownload one song as EPUB.
exportSongMusicXmlGETDownload one song as a MusicXML score — the words laid under a staff, one note per word, ready to set to music in a notation program. importDocument reads the same format back.
exportSongsTxtGETDownload the project's songs as one text songbook. Add ids to narrow it to a selection.
exportSongsPdfGETDownload the project's songs as one PDF songbook.
exportSongsDocxGETDownload the project's songs as one Word (.docx) songbook.
exportSongsEpubGETDownload the project's songs as one EPUB songbook.
exportSongsMusicXmlGETDownload the project's songs as one MusicXML score, each song a titled section on its own page. Add ids to narrow it to a selection.
exportNotesTxtGETDownload the project's notes as one text file. Add ids to narrow it to a selection. Advertised on the document collection once it holds a note — the notes counterpart of exportSongsTxt.
exportNotesPdfGETDownload the project's notes as one PDF.
exportNotesDocxGETDownload the project's notes as one Word (.docx) file.
exportNotesEpubGETDownload the project's notes as one EPUB. There is deliberately no MusicXML twin: a score of scene notes is not a thing, and the endpoint refuses one.
addCommentPOSTLeave a comment on an element.
sendInvitationPOSTInvite someone to a project by email. A collaborator invitation must name a teamId from inviteTeams; a viewOnly one must not.
inviteTeamsGETThe teams a collaborator may be invited into: the ones this project is assigned to. An empty collection means the project can take no collaborators until it is assigned a team.
projectTeamsGETEvery team the writer could assign this project to, each with an assigned flag — the production page's team checkboxes. Read-only: to change the assignment, send the chosen ids back as teamIds through update. Advertised only to an editor.
revokeDELETEWithdraw an outstanding invitation, or remove a registered passkey.
assignProductionsPUTReplace the set of productions a team is attached to.
setDefaultPOSTMake this edition the one opened when no edition is named.
setPublishedPOSTMake this edition the one view-only readers see. Independent of the default, so a writer can work in a draft while readers stay on the last published cut.
purgeDELETEDelete one item from the trash for good. Not recoverable.
emptyTrashDELETEDelete everything in the trash for good. Not recoverable.
bulkSetTypePOSTRetype every element in a selection. Advertised on the block collection rather than a block, since it acts on a set of them.
bulkAddTagsPOSTAdd tags to every element in a selection.
bulkFormatPOSTSet alignment, font, style or highlight across a selection in one undo checkpoint. Each field applies only when present; style is a per-element toggle rather than a set, so a mixed selection comes back inverted. Pass clearHighlight to remove a tint, or clearFont to reset a font to the default, since a blank value means "leave alone".
bulkReplacePOSTFind and replace across a selection. find and replace are both literal — never regular expressions. Character cues are skipped unless includeCharacterCues is set, because a cue mirrors its person record.
bulkDeletePOSTDelete every item in a selection — elements when it rides on the block collection, songs when it rides on the document collection. Recoverable from the project's trash either way.
archivePOSTPut one thing aside: it leaves its list but keeps everything in it and stays readable. On a song or note it keeps the lyrics, versions and script insertions; on a project it keeps the script, songs, notes, editions and versions, and the project stays openable and exportable. Answers with the refreshed collection it left — documents or projects. Offered on songs and notes alike; unlike the export and email rels there is nothing song-shaped about archiving.
unarchivePOSTBring one thing back from the archive to its list. Answers with the refreshed archive. Archiving a project drops it as anyone's default; unarchiving does not put that back. Also offered on an archived song or note fetched by id — an archived document is still opened and edited in place, and there the way back is the only direction there is: archive and this one are never advertised together.
bulkArchivePOSTArchive every document in a selection. Rides on the document collection and takes ids. Unlike bulkDelete it is not songs-only, since notes archive too; ids already archived or outside the project are skipped.
bulkUnarchivePOSTBring every item in a selection back from the archive, and the one bulk rel that rides on the archive rather than the list it feeds — that is where the selection is made. Takes ids; answers with the refreshed archive. Offered on both archives, documents and projects, and only when there is something in one to tick. Ids that are not in the archive are skipped, so a selection that went stale while the sheet was open still does what it can.
